JVM 内存模型与垃圾回收

2025年4月12日
|编辑此页

概述

JVM（Java Virtual Machine）是 Java 程序的运行环境，负责将字节码转换为机器码并执行。理解 JVM 的内存模型和垃圾回收机制对于编写高性能 Java 程序至关重要。

JVM 内存结构

1. 程序计数器（Program Counter Register）

  • 作用：记录当前线程执行的字节码指令位置
  • 特点：线程私有，不会发生内存溢出
  • 说明：如果线程执行的是 Java 方法，计数器记录的是正在执行的虚拟机字节码指令地址；如果执行的是 Native 方法，计数器值为空（Undefined）

2. Java 虚拟机栈（Java Virtual Machine Stacks）

  • 作用：存储方法调用的局部变量、操作数栈、动态链接、方法出口等信息
  • 特点：线程私有，生命周期与线程相同
  • 异常：栈深度过大抛出 StackOverflowError；栈扩展失败抛出 OutOfMemoryError

3. 本地方法栈（Native Method Stack）

  • 作用：为 Native 方法服务
  • 特点：线程私有
  • 异常：StackOverflowError、OutOfMemoryError

4. 堆（Heap）

  • 作用：存储对象实例和数组
  • 特点：线程共享，垃圾回收的主要区域
  • 异常：OutOfMemoryError

堆内存结构

堆
├── 新生代（Young Generation）
│   ├── Eden 区
│   ├── Survivor 0 区（From）
│   └── Survivor 1 区（To）
└── 老年代（Old Generation / Tenured Generation）

5. 方法区（Method Area）

  • 作用：存储类信息、常量、静态变量、即时编译器编译后的代码等
  • 特点：线程共享
  • 异常：OutOfMemoryError

6. 运行时常量池（Runtime Constant Pool）

  • 作用：存储类中的常量池、字面量、符号引用
  • 特点：方法区的一部分

7. 直接内存（Direct Memory）

  • 作用：NIO 使用，直接分配堆外内存
  • 特点：不受 JVM 堆内存限制
  • 异常：OutOfMemoryError

垃圾回收（GC）

1. 垃圾回收判定

引用计数法

  • 原理：对象被引用一次，计数器加 1；引用失效，计数器减 1；计数器为 0 时可回收
  • 缺点：无法解决循环引用问题

可达性分析（主流）

  • 原理：从 GC Roots 开始向下搜索，搜索走过的路径称为引用链，如果一个对象到 GC Roots 没有任何引用链相连，则证明该对象不可用
  • GC Roots 包括：
    • 虚拟机栈中引用的对象
    • 方法区中类静态属性引用的对象
    • 方法区中常量引用的对象
    • 本地方法栈中 JNI 引用的对象

2. 垃圾回收算法

标记-清除算法（Mark-Sweep）

  • 步骤：标记需要回收的对象 → 清除标记的对象
  • 缺点：效率不高，产生大量不连续的内存碎片

复制算法（Copying）

  • 步骤：将存活对象复制到另一块内存，清除原内存
  • 优点：没有内存碎片，效率高
  • 缺点：内存利用率低
  • 应用：新生代

标记-整理算法（Mark-Compact）

  • 步骤：标记需要回收的对象 → 将存活对象向一端移动 → 清除边界外的内存
  • 优点：没有内存碎片
  • 缺点：效率较低
  • 应用：老年代

分代收集算法

  • 原理：根据对象存活周期将内存分为新生代和老年代，根据不同代采用不同的收集算法
  • 新生代：复制算法
  • 老年代：标记-清除或标记-整理算法

3. 垃圾收集器

Serial 收集器

  • 特点：单线程收集，进行 GC 时必须暂停其他工作线程
  • 适用：新生代、老年代
  • 优点：简单高效（单 CPU 环境下）
  • 缺点：停顿时间长

Parallel 收集器

  • 特点：多线程收集，关注吞吐量
  • 适用：新生代、老年代
  • 优点：效率高
  • 缺点：停顿时间较长

CMS（Concurrent Mark Sweep）收集器

  • 特点：以获取最短回收停顿时间为目标
  • 适用：老年代
  • 步骤：初始标记 → 并发标记 → 重新标记 → 并发清除
  • 缺点：对 CPU 资源敏感，产生内存碎片

G1（Garbage First）收集器

  • 特点：面向服务端，可预测停顿时间
  • 适用：新生代、老年代
  • 优点：停顿时间可控，无内存碎片
  • 原理：将堆划分为多个 Region，根据每个 Region 的垃圾堆积价值进行回收

JVM 内存溢出示例

1. 堆内存溢出

public class OOMDemo {
    // JVM 启动参数：-Xms20m -Xmx20m -XX:+HeapDumpOnOutOfMemoryError
    public static void main(String[] args) {
        List<byte[]> list = new ArrayList<>();
        int count = 0;
        while (true) {
            list.add(new byte[1024 * 1024]); // 1MB 数组
            System.out.println("分配第" + (++count) + "MB");
        }
    }
}

解决方法：

  • 增加堆内存：-Xms512m -Xmx512m
  • 分析内存泄漏或内存溢出

2. 栈内存溢出

public class StackOverflowDemo {
    public static void main(String[] args) {
        recursion();
    }

    private static void recursion() {
        recursion();  // 无限递归
    }
}

解决方法：

  • 增加栈大小：-Xss256k
  • 优化递归深度

3. 方法区溢出

public class MethodAreaOOM {
    public static void main(String[] args) {
        while (true) {
            Enhancer enhancer = new Enhancer();
            enhancer.setSuperclass(OOMObject.class);
            enhancer.setUseCache(false);
            enhancer.setCallback(new MethodInterceptor() {
                @Override
                public Object intercept(Object obj, Method method, Object[] args, MethodProxy proxy) throws Throwable {
                    return proxy.invokeSuper(obj, args);
                }
            });
            enhancer.create();
        }
    }

    static class OOMObject {}
}

解决方法：

  • 增加方法区大小：-XX:MaxMetaspaceSize=256m
  • 减少动态类的生成

JVM 可见性问题

1. 可见性问题示例

public class VisibilityDemo {
    private static boolean flag = false;

    public static void main(String[] args) throws InterruptedException {
        new Thread(() -> {
            while (!flag) {
                // 空循环
            }
            System.out.println("线程感知到flag变为true");
        }).start();

        Thread.sleep(1000);
        flag = true;
        System.out.println("主线程修改flag=true");
    }
}

问题：子线程可能无法感知主线程对 flag 的修改，导致无限循环。

2. 解决方法

方法1：使用 volatile

private static volatile boolean flag = false;

方法2：使用 synchronized

synchronized (lock) {
    while (!flag) {
        // 空循环
    }
}

方法3：使用 AtomicBoolean

private static AtomicBoolean flag = new AtomicBoolean(false);

JVM 调优参数

1. 内存参数

-Xms512m          # 初始堆大小
-Xmx512m          # 最大堆大小
-Xmn256m          # 新生代大小
-XX:MetaspaceSize=128m   # 元空间初始大小
-XX:MaxMetaspaceSize=256m # 元空间最大大小
-Xss256k          # 线程栈大小

2. 垃圾回收参数

-XX:+UseSerialGC           # 使用 Serial 收集器
-XX:+UseParallelGC        # 使用 Parallel 收集器
-XX:+UseConcMarkSweepGC    # 使用 CMS 收集器
-XX:+UseG1GC              # 使用 G1 收集器
-XX:MaxGCPauseMillis=200   # 最大 GC 停顿时间

3. 分析参数

-XX:+PrintGCDetails        # 打印 GC 详细信息
-XX:+PrintGCDateStamps     # 打印 GC 时间戳
-Xloggc:gc.log            # GC 日志文件
-XX:+HeapDumpOnOutOfMemoryError  # OOM 时生成堆转储文件
-XX:HeapDumpPath=/tmp/heapdump.hprof  # 堆转储文件路径

JVM 分析工具

1. jps

查看正在运行的 Java 进程。

jps -l

2. jstat

查看 JVM 统计信息。

jstat -gcutil <pid> 1000 10  # 每秒打印一次，共 10 次

3. jmap

查看堆内存信息。

jmap -heap <pid>                    # 查看堆配置
jmap -histo:live <pid>              # 查看堆中对象统计
jmap -dump:format=b,file=heap.hprof <pid>  # 导出堆转储文件

4. jstack

查看线程堆栈信息。

jstack <pid>

5. jconsole

JVM 监控和管理控制台（图形界面）。

6. jvisualvm

JVM 可视化监控工具（图形界面）。

最佳实践

  1. 合理设置堆内存：根据应用需求设置合适的堆大小
  2. 选择合适的垃圾收集器：根据应用特点选择 GC
  3. 监控 JVM 运行状态：定期检查 GC 日志和内存使用情况
  4. 避免内存泄漏：及时释放不再使用的对象
  5. 使用对象池：频繁创建销毁的对象使用对象池
  6. 注意可见性问题：多线程环境使用 volatile 或同步机制

常见面试题

1. JVM 内存结构包括哪些部分？

答：程序计数器、Java 虚拟机栈、本地方法栈、堆、方法区、运行时常量池、直接内存。

2. 垃圾回收算法有哪些？

答：标记-清除算法、复制算法、标记-整理算法、分代收集算法。

3. 常见的垃圾收集器有哪些？

答：Serial、Parallel、CMS、G1。Serial 是单线程，Parallel 是多线程关注吞吐量，CMS 关注低停顿，G1 是面向服务端的可预测停顿时间收集器。

4. 如何判断对象可以被回收？

答：引用计数法和可达性分析。引用计数法无法解决循环引用问题，可达性分析从 GC Roots 开始搜索，无法到达的对象可被回收。

5. volatile 的作用？

答：保证可见性、禁止指令重排序。volatile 修饰的变量修改后对其他线程立即可见，适用于简单的状态标志场景。

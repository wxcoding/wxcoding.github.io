Java 线程池 ThreadPoolExecutor 详解

2025年1月21日
|编辑此页

概述

线程池（ThreadPoolExecutor）是 Java 并发包中用于管理和复用线程的核心类。线程池可以减少线程创建和销毁的开销，提高系统性能，并提供线程管理的统一接口。

为什么使用线程池

  1. 降低资源消耗：复用已创建的线程，减少线程创建和销毁的开销
  2. 提高响应速度：任务到达时，无需等待线程创建即可执行
  3. 提高线程可管理性：统一分配、调优和监控线程
  4. 控制并发数：限制最大线程数，避免系统资源耗尽

ThreadPoolExecutor 核心参数

构造函数

public ThreadPoolExecutor(
    int corePoolSize,              // 核心线程数
    int maximumPoolSize,           // 最大线程数
    long keepAliveTime,            // 线程空闲时间
    TimeUnit unit,                // 时间单位
    BlockingQueue<Runnable> workQueue,  // 任务队列
    ThreadFactory threadFactory,   // 线程工厂
    RejectedExecutionHandler handler    // 拒绝策略
)

参数详解

1. corePoolSize - 核心线程数

  • 线程池中保持存活的最小线程数
  • 即使线程空闲，也不会被回收（除非设置 allowCoreThreadTimeOut）
  • 默认情况下，核心线程会一直存活

2. maximumPoolSize - 最大线程数

  • 线程池允许创建的最大线程数
  • 当任务队列满时，如果当前线程数 < maximumPoolSize，会创建新线程
  • 必须大于等于 corePoolSize

3. keepAliveTime - 线程空闲时间

  • 当线程数 > corePoolSize 时，空闲线程的最大存活时间
  • 超过该时间，空闲线程会被回收
  • 默认情况下，只对非核心线程生效

4. unit - 时间单位

  • keepAliveTime 的时间单位
  • 常用：TimeUnit.SECONDS、TimeUnit.MILLISECONDS

5. workQueue - 任务队列

  • 用于保存等待执行任务的阻塞队列
  • 常用队列：
    • ArrayBlockingQueue：有界队列，必须指定容量
    • LinkedBlockingQueue：无界队列（实际是 Integer.MAX_VALUE）
    • SynchronousQueue：不存储元素的队列，每个插入操作必须等待另一个线程的移除操作
    • PriorityBlockingQueue：具有优先级的无界阻塞队列

6. threadFactory - 线程工厂

  • 用于创建新线程的工厂
  • 可以自定义线程名称、优先级、是否为守护线程等

7. handler - 拒绝策略

  • 当任务队列满且线程数达到 maximumPoolSize 时的处理策略
  • 内置策略：
    • AbortPolicy（默认）：抛出 RejectedExecutionException
    • CallerRunsPolicy：由调用者线程执行任务
    • DiscardPolicy：直接丢弃任务，不抛出异常
    • DiscardOldestPolicy：丢弃队列中最老的任务，然后重新提交

线程池工作流程

1. 任务提交
   ↓
2. 线程数 < corePoolSize？
   ├─ 是 → 创建新线程执行任务
   └─ 否 → 继续
   ↓
3. 任务队列未满？
   ├─ 是 → 任务加入队列等待
   └─ 否 → 继续
   ↓
4. 线程数 < maximumPoolSize？
   ├─ 是 → 创建新线程执行任务
   └─ 否 → 继续
   ↓
5. 执行拒绝策略

自定义线程池示例

import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;

public class ThreadPoolUtil {

    /**
     * 私有静态实例：全局单例线程池
     */
    private static final ThreadPoolExecutor BUSINESS_POOL;

    /**
     * 静态初始化块：在类加载时创建并配置线程池
     */
    static {
        int cpu = Runtime.getRuntime().availableProcessors();
        BUSINESS_POOL = new ThreadPoolExecutor(
                // corePoolSize：基础并发数，保持该数量的线程常驻
                cpu,
                // maximumPoolSize：最大并发数，允许突发时扩容到 cpu * 2
                cpu * 2,
                // keepAliveTime：超过 corePoolSize 后，空闲线程在回收前保持的时间
                60L,
                TimeUnit.SECONDS,
                // 队列大小为 200 的有界队列，避免无限制排队导致 OOM
                new ArrayBlockingQueue<>(200),
                // 自定义线程工厂，方便线程命名和设置 daemon 状态
                new CustomThreadFactory("business-pool-"),
                // 拒绝策略：CallerRunsPolicy 将任务回退到提交者线程
                new ThreadPoolExecutor.CallerRunsPolicy()
        );
    }

    /**
     * 提交无返回值任务（Runnable）
     */
    public static void execute(Runnable task) {
        BUSINESS_POOL.execute(task);
    }

    /**
     * 提交有返回值任务（Callable），返回 Future
     */
    public static <T> Future<T> submit(Callable<T> task) {
        return BUSINESS_POOL.submit(task);
    }

    /**
     * 暴露线程池实例
     */
    public static ThreadPoolExecutor getPool() {
        return BUSINESS_POOL;
    }

    /**
     * 关闭线程池
     */
    public static void shutdown() {
        BUSINESS_POOL.shutdown();
    }

    /**
     * 自定义线程工厂
     */
    static class CustomThreadFactory implements ThreadFactory {
        private final String prefix;
        private int num = 0;

        public CustomThreadFactory(String prefix) {
            this.prefix = prefix;
        }

        @Override
        public Thread newThread(Runnable r) {
            Thread thread = new Thread(r, prefix + (num++));
            thread.setDaemon(false);
            return thread;
        }
    }
}

自定义线程工厂

public class NamingThreadFactory implements ThreadFactory {
    private final AtomicInteger sequence = new AtomicInteger();
    private final String prefix;

    public NamingThreadFactory(String prefix) {
        this.prefix = prefix;
    }

    @Override
    public Thread newThread(Runnable task) {
        Thread thread = new Thread(task);
        thread.setName(prefix + "-" + sequence.incrementAndGet());
        thread.setDaemon(false);
        thread.setPriority(Thread.NORM_PRIORITY);
        return thread;
    }
}

线程池配置建议

1. CPU 密集型任务

int corePoolSize = Runtime.getRuntime().availableProcessors() + 1;
int maximumPoolSize = corePoolSize * 2;

2. IO 密集型任务

int corePoolSize = Runtime.getRuntime().availableProcessors() * 2;
int maximumPoolSize = corePoolSize * 2;

3. 混合型任务

根据实际压测结果调整参数。

Executors 工具类（不推荐使用）

1. newFixedThreadPool

// 不推荐：使用无界 LinkedBlockingQueue，可能导致 OOM
ExecutorService executor = Executors.newFixedThreadPool(10);

2. newSingleThreadExecutor

// 不推荐：使用无界 LinkedBlockingQueue，可能导致 OOM
ExecutorService executor = Executors.newSingleThreadExecutor();

3. newCachedThreadPool

// 不推荐：maximumPoolSize 为 Integer.MAX_VALUE，可能创建过多线程
ExecutorService executor = Executors.newCachedThreadPool();

4. newScheduledThreadPool

// 不推荐：使用无界 DelayedWorkQueue，可能导致任务堆积
ScheduledExecutorService executor = Executors.newScheduledThreadPool(10);

推荐：直接使用 ThreadPoolExecutor，明确指定所有参数。

线程池状态

状态说明
RUNNING接受新任务，处理队列任务
SHUTDOWN不接受新任务，处理队列任务
STOP不接受新任务，不处理队列任务，中断正在执行的任务
TIDYING所有任务已终止，线程数归零
TERMINATED线程池完全终止

线程池关闭

1. shutdown()

executor.shutdown();
// 不接受新任务，已提交任务会继续执行

2. shutdownNow()

List<Runnable> tasks = executor.shutdownNow();
// 不接受新任务，尝试中断正在执行的任务，返回未执行的任务

3. awaitTermination()

executor.shutdown();
try {
    if (!executor.awaitTermination(60, TimeUnit.SECONDS)) {
        executor.shutdownNow();
    }
} catch (InterruptedException e) {
    executor.shutdownNow();
}

线程池监控

ThreadPoolExecutor executor = new ThreadPoolExecutor(...);

// 获取核心线程数
int corePoolSize = executor.getCorePoolSize();

// 获取最大线程数
int maximumPoolSize = executor.getMaximumPoolSize();

// 获取当前线程数
int poolSize = executor.getPoolSize();

// 获取活跃线程数
int activeCount = executor.getActiveCount();

// 获取队列任务数
int queueSize = executor.getQueue().size();

// 获取已完成任务数
long completedTaskCount = executor.getCompletedTaskCount();

最佳实践

  1. 使用 ThreadPoolExecutor：避免使用 Executors 工具类
  2. 合理设置参数：根据任务类型和压测结果调整参数
  3. 自定义线程工厂：为线程设置有意义的名称
  4. 使用有界队列：避免任务无限堆积导致 OOM
  5. 选择合适的拒绝策略：根据业务需求选择
  6. 及时关闭线程池：应用关闭时调用 shutdown()
  7. 监控线程池状态：定期检查线程池健康状态
  8. 避免在线程池中阻塞：避免长时间阻塞任务

常见面试题

1. 线程池的核心参数有哪些？

答：corePoolSize（核心线程数）、maximumPoolSize（最大线程数）、keepAliveTime（空闲时间）、unit（时间单位）、workQueue（任务队列）、threadFactory（线程工厂）、handler（拒绝策略）。

2. 线程池的工作流程？

答：任务提交后，如果线程数 < corePoolSize，创建新线程；如果队列未满，任务加入队列；如果线程数 < maximumPoolSize，创建新线程；否则执行拒绝策略。

3. 为什么不推荐使用 Executors 工具类？

答：Executors 创建的线程池使用无界队列或允许线程数无限增长，可能导致 OOM 或创建过多线程。建议直接使用 ThreadPoolExecutor，明确指定所有参数。

4. 如何合理设置线程池参数？

答：CPU 密集型任务设置 corePoolSize = CPU 核心数 + 1；IO 密集型任务设置 corePoolSize = CPU 核心数 * 2；根据实际压测结果调整参数。

5. 线程池的拒绝策略有哪些？

答：AbortPolicy（抛出异常）、CallerRunsPolicy（调用者执行）、DiscardPolicy（丢弃任务）、DiscardOldestPolicy（丢弃最老任务）。

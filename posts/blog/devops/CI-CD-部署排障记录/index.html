CI/CD 低配服务器部署排障记录（2026-10-31）

环境：GitHub Actions（境外 runner）→ 阿里云 ACR 个人版（杭州）→ 阿里云轻量应用服务器（2vCPU / 1GiB / 杭州），Docker Compose 单机部署（postgres + redis + afs-server + afs-web）。

一、根因总览

层面问题状态
构建镜像内重复 Maven/npm 构建，跨国推送 10m51s✅ 已修复
部署脚本pull --timeout flag 不兼容 Compose v5✅ 已修复
健康检查afs-web healthcheck 误报 unhealthy 触发回滚✅ 已修复
镜像仓库push access denied（凭据/仓库权限）✅ 已恢复
网络VPC 内网拉镜像不可行（个人版 ACR 不支持）⛔ 已回退公网
服务器规格2C1G，1GiB 内存物理不足，部署峰值必卡死⚠️ 待升配

二、构建阶段：镜像构建推送慢（10m51s → ~1m）

现象：docker-build 阶段推送镜像耗时 10 分 51 秒。

根因（两个叠加）：

  1. GitHub runner 在境外，推送阿里云 ACR（国内）是跨国传输；
  2. Dockerfile 在镜像内重复构建——CI 的 build 阶段已经打过 jar / dist，镜像里又跑一遍 mvn package / npm run build，层缓存全失效，推送量大。

修复：

  • afs-server/Dockerfile、afs-web/Dockerfile 删掉 builder 阶段，直接 COPY target/*.jar / COPY dist（CI 产物经 artifact 传入）；
  • ci-cd.yml 两处 cache-to: type=gha,mode=max → mode=min（不再导出 builder 中间层）；
  • 修复 .dockerignore：构建上下文是子目录（./afs-server、./afs-web），路径模式必须相对 context；afs-web/.dockerignore 原来忽略了 dist，会导致 COPY 不到产物。

效果：构建应用 1m11s；首次推送后基础层已在 ACR，之后每次只推 jar 层（几十 MB）+ dist 层（几 MB）。

注意：本地 docker compose up -d --build 前需先 mvn package 和 npm run build（docker-compose.yml 头部注释已写明）。

三、部署阶段

3.1 unknown flag: --timeout

现象：服务器部署失败，docker compose pull --timeout 3000 报 unknown flag。

根因：服务器是 Compose v5.6.1，v5 大版本移除了 pull 子命令的 --timeout flag（v2.x 有）。不是版本太旧，是太新。

修复：ci-cd.yml 中删除该 flag。up -d --wait --wait-timeout（回滚逻辑依赖）在 v5 中保留，不受影响。

3.2 afs-web unhealthy → 自动回滚

现象：postgres / redis / afs-server 全部 Healthy，afs-web 被判 unhealthy，触发自动回滚。

排查过程：

docker inspect --format='{{json .State.Health}}' afs-web
# Output: "wget: can't connect to remote host: Connection refused"
docker logs afs-web   # access log 全是正常 200 请求，nginx 活得好好的

根因：容器内 localhost 解析到 IPv6 ::1，而 nginx listen 80; 只绑 IPv4。alpine 的 busybox wget 连 ::1:80 被拒且未回退 IPv4。从外部（IPv4 端口映射）访问完全正常，是健康检查自身误报。该 healthcheck 自写下起从未工作过（afs-web 第一次真正启动）。

修复：docker-compose.prod.yml 与 docker-compose.yml 中健康检查改用 127.0.0.1：

test: ["CMD-SHELL", "wget -q --spider http://127.0.0.1/health || exit 1"]

经验：健康检查不是形式主义——本次回滚逻辑（up --wait 失败 → 恢复 PREV_TAG）正因为有它才兜住。探活端点要轻量专用（nginx return 200 'ok'），Java 服务必须配 start_period（prod 已配 60s）。

3.3 push access denied

现象：docker-build 推送报 push access denied, repository does not exist or may require authorization，但 login 步骤成功。

结论：login 成功 ≠ 有推送权限。排查路径：本地用同凭据 docker login + push 一个 hello-world 测试镜像定位；检查 ACR 访问凭证（需用固定密码非临时密码）、命名空间下仓库是否存在、GitHub Secrets 四个值（ALIYUN_ACR_REGISTRY / NAMESPACE / USERNAME / PASSWORD，注意 REGISTRY 不带 https://、不带尾 /）。后重设凭证后恢复。

3.4 VPC 内网拉镜像：不可行（已回退）

目的：绕开公网小带宽，内网拉镜像不限速。

结论：个人版 ACR 不支持 VPC 访问（企业版功能，控制台无“访问控制”菜单）。VPC 域名虽能解析到 100.x 内网地址，但 443 直接超时。验证命令：

curl -v --max-time 10 https://<vpc域名>/v2/   # 401=通;超时=不通

处置：删除 GitHub Secret ALIYUN_ACR_REGISTRY_VPC 即回退公网（ci-cd.yml 中为 ${{ secrets.ALIYUN_ACR_REGISTRY_VPC || secrets.ALIYUN_ACR_REGISTRY }}，未配置自动 fallback）。

3.5 drone-ssh warning（无害）

部署日志中多条 DRONE_SSH_PREV_COMMAND_EXIT_CODE variable is not set —— appleboy/ssh-action（drone-ssh v1.8.0）自身内部变量的已知日志，可无视。

四、服务器卡死：最终根因是规格

现象：一部署服务器整机卡死，SSH 敲不动；拉镜像最低 21KB/s。

根因：轻量应用服务器 2vCPU / 1GiB。内存账：

占用方约需内存
afs-server（JVM 堆 512m + JVM 开销）~800MB
postgres~300MB
redis + nginx~100MB
系统 + dockerd~500MB
合计~1.6GB，超物理内存 60%
  • 稳态（~1GB）贴着红线能活，所以之前服务一直在跑；
  • 部署峰值（pull 解压 + Java 冷启动 JIT + 新旧容器交替）~1.6GB → 顶穿 → OOM / 僵死；
  • 回滚能成功是因为旧镜像已在本地，省掉解压峰值；
  • 带宽标称 200Mbps 是峰值，轻量套餐月流量包超限后限速 → 解释拉镜像龟速。

应急（不升配时的保底）：

fallocate -l 3G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

swap 换不卡死，代价是内存不足时响应变慢。Java 堆可降至 -Xmx384m。

根治：升配 2C4G（底线 2C2G）。SSH 卡死时可用阿里云控制台 VNC 远程连接，或控制台重启实例（容器均 restart: always 自动拉起）。

诊断命令：

free -h; nproc
dmesg | grep -i -A3 "out of memory" | tail -20   # OOM 记录
docker stats --no-stream

五、数据库外部连接：SSH 隧道方案

结论：不开放公网 5432。Navicat 走 SSH 隧道。

  • compose 中 postgres 映射 127.0.0.1:5432:5432（只绑回环，公网不可达）——docker-compose.prod.yml 已改；
  • Navicat SSH 标签页：主机 <服务器IP>、端口 22、用户 root；
  • 常规标签页：主机 127.0.0.1、端口 5432、库 afs、用户 postgres、密码取服务器 .env 的 POSTGRES_PASSWORD；
  • 临时查看可 docker exec -it afs-postgres psql -U postgres -d afs；
  • 安全组直放 5432 = 全网爆破目标，即使要做也必须限源 IP（你的IP/32），不推荐。

六、SSH 认证备忘

  • CI 用私钥（GitHub Secret SERVER_SSH_KEY）连服务器；服务器 sshd 到固定文件 ~/.ssh/authorized_keys 中逐行匹配公钥，任一行匹配即通过；
  • 权限必须 ~/.ssh = 700、authorized_keys = 600，属主为登录用户，否则 sshd（StrictModes）直接忽略；
  • 排查：stat -c '%a %U:%G %n' ~/.ssh ~/.ssh/authorized_keys；sudo journalctl -u sshd -n 50。

七、改动文件清单

文件改动
afs-server/Dockerfile删 maven builder，直接 COPY jar
afs-web/Dockerfile删 node builder，直接 COPY dist
.github/workflows/ci-cd.ymlmode=min；删 pull --timeout；deploy job 增加 VPC REGISTRY fallback（未配置则公网）
afs-server/.dockerignore路径改为相对 context；target/ 排除但保留 *.jar
afs-web/.dockerignore放行 dist（关键）
docker-compose.yml头部注释补前置构建步骤；afs-web healthcheck 改 127.0.0.1
docker-compose.prod.ymlafs-web healthcheck 改 127.0.0.1；postgres 增加 127.0.0.1:5432:5432

八、遗留事项

  • 服务器升配至 2C4G（根治卡死与部署慢）
  • 升配前：添加 swap；.env 中 JAVA_OPTS 可降至 -Xmx384m
  • 轻量控制台查月流量使用情况（解释拉镜像限速）
  • 如需 push 即自动部署：注释 deploy job 的 if，并将 notify 的 if 改为 if: always()（注意 environment: production 的审批配置）

设计模式-单例模式

2023年3月15日
|编辑此页

概述

单例模式（Singleton Pattern）是一种创建型设计模式，确保一个类只有一个实例，并提供一个全局访问点。单例模式常用于配置管理、数据库连接池、日志管理等场景。

单例模式特点

  • 唯一实例：类只能有一个实例
  • 全局访问：提供一个全局访问点
  • 自我实例化：类自己负责创建自己的实例

单例模式实现方式

1. 饿汉式（线程安全）

public class Singleton {
    // 类加载时就创建实例
    private static final Singleton INSTANCE = new Singleton();

    private Singleton() {
        // 私有构造方法
    }

    public static Singleton getInstance() {
        return INSTANCE;
    }
}

优缺点

  • 优点：线程安全，实现简单
  • 缺点：类加载时就创建实例，可能造成资源浪费

2. 懒汉式（线程不安全）

public class Singleton {
    private static Singleton instance;

    private Singleton() {
        // 私有构造方法
    }

    public static Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}

优缺点

  • 优点：延迟加载，节省资源
  • 缺点：线程不安全，多线程环境下可能创建多个实例

3. 懒汉式（同步方法）

public class Singleton {
    private static Singleton instance;

    private Singleton() {
        // 私有构造方法
    }

    public static synchronized Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}

优缺点

  • 优点：线程安全
  • 缺点：每次获取实例都需要同步，性能较差

4. 双重检查锁（推荐）

public class Singleton {
    // volatile 禁止指令重排序
    private static volatile Singleton singleton;

    private Singleton() {
        // 私有构造方法
    }

    public static Singleton getInstance() {
        if (singleton == null) {
            synchronized (Singleton.class) {
                if (singleton == null) {
                    singleton = new Singleton();
                }
            }
        }
        return singleton;
    }
}

优缺点

  • 优点：线程安全，延迟加载，性能较好
  • 缺点：实现稍复杂

为什么需要 volatile？

singleton = new Singleton();

这行代码在 JVM 中分为三步：

  1. 分配内存空间
  2. 初始化对象
  3. 将引用指向分配的内存地址

如果不使用 volatile，可能发生指令重排序，导致步骤 2 和 3 交换，其他线程可能获取到未初始化的对象。

5. 静态内部类（推荐）

public class Singleton {
    private Singleton() {
        // 私有构造方法
    }

    private static class SingletonHolder {
        private static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return SingletonHolder.INSTANCE;
    }
}

优缺点

  • 优点：线程安全，延迟加载，性能好，实现简单
  • 缺点：无

原理

利用类加载机制保证线程安全：

  • 外部类加载时不会加载内部类
  • 只有调用 getInstance() 时才会加载内部类
  • JVM 保证类加载过程是线程安全的

6. 枚举（最佳实践）

public enum Singleton {
    INSTANCE;

    public void doSomething() {
        // 业务方法
    }
}

使用

Singleton singleton = Singleton.INSTANCE;
singleton.doSomething();

优缺点

  • 优点：
    • 线程安全（JVM 保证）
    • 序列化安全（枚举天然支持序列化）
    • 防止反射攻击（反射无法创建枚举实例）
    • 代码简洁
  • 缺点：无

为什么枚举是实现单例的最佳方式？

  1. 线程安全：JVM 保证枚举实例的线程安全初始化
  2. 序列化安全：枚举天然支持序列化，不会创建新实例
  3. 防止反射攻击：反射无法创建枚举实例
  4. 代码简洁：实现简单，无需额外代码

单例模式的破坏

1. 序列化破坏

// 序列化
ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("singleton.ser"));
oos.writeObject(singleton);
oos.close();

// 反序列化
ObjectInputStream ois = new ObjectInputStream(new FileInputStream("singleton.ser"));
Singleton newInstance = (Singleton) ois.readObject();
ois.close();

// newInstance != singleton，单例被破坏

解决方案

实现 readResolve() 方法：

private Object readResolve() {
    return getInstance();
}

2. 反射破坏

Constructor<Singleton> constructor = Singleton.class.getDeclaredConstructor();
constructor.setAccessible(true);
Singleton newInstance = constructor.newInstance();
// newInstance != singleton，单例被破坏

解决方案

在构造方法中添加检查：

private Singleton() {
    if (singleton != null) {
        throw new RuntimeException("不允许创建多个实例");
    }
}

3. 克隆破坏

Singleton clone = singleton.clone();
// clone != singleton，单例被破坏

解决方案

重写 clone() 方法：

@Override
protected Object clone() throws CloneNotSupportedException {
    return getInstance();
}

实际应用场景

1. 配置管理器

public class ConfigManager {
    private static volatile ConfigManager instance;
    private Properties properties;

    private ConfigManager() {
        properties = new Properties();
        // 加载配置
    }

    public static ConfigManager getInstance() {
        if (instance == null) {
            synchronized (ConfigManager.class) {
                if (instance == null) {
                    instance = new ConfigManager();
                }
            }
        }
        return instance;
    }

    public String getProperty(String key) {
        return properties.getProperty(key);
    }
}

2. 数据库连接池

public class ConnectionPool {
    private static volatile ConnectionPool instance;
    private List<Connection> connections;

    private ConnectionPool() {
        connections = new ArrayList<>();
        // 初始化连接池
    }

    public static ConnectionPool getInstance() {
        if (instance == null) {
            synchronized (ConnectionPool.class) {
                if (instance == null) {
                    instance = new ConnectionPool();
                }
            }
        }
        return instance;
    }

    public Connection getConnection() {
        // 获取连接
    }
}

3. 日志管理器

public class LogManager {
    private static volatile LogManager instance;
    private Logger logger;

    private LogManager() {
        logger = Logger.getLogger(LogManager.class.getName());
    }

    public static LogManager getInstance() {
        if (instance == null) {
            synchronized (LogManager.class) {
                if (instance == null) {
                    instance = new LogManager();
                }
            }
        }
        return instance;
    }

    public void log(String message) {
        logger.info(message);
    }
}

最佳实践

  1. 优先使用枚举：枚举是实现单例的最佳方式
  2. 使用双重检查锁：如果枚举不适用，使用双重检查锁
  3. 考虑延迟加载：如果实例创建开销大，使用延迟加载
  4. 防止破坏：如果需要序列化，实现 readResolve() 方法
  5. 线程安全：确保单例在多线程环境下的线程安全

常见面试题

1. 单例模式的实现方式有哪些？

答：饿汉式、懒汉式（线程不安全）、懒汉式（同步方法）、双重检查锁、静态内部类、枚举。推荐使用枚举或静态内部类。

2. 双重检查锁为什么需要 volatile？

答：禁止指令重排序。new Singleton() 分为三步：分配内存、初始化对象、将引用指向内存。如果不使用 volatile，可能发生指令重排序，导致其他线程获取到未初始化的对象。

3. 为什么枚举是实现单例的最佳方式？

答：枚举单例具有以下优势：JVM 保证线程安全、天然支持序列化、防止反射攻击、代码简洁。

4. 如何防止单例被破坏？

答：实现 readResolve() 方法防止序列化破坏；在构造方法中添加检查防止反射破坏；重写 clone() 方法防止克隆破坏。

5. 单例模式的优缺点？

答：优点：减少内存开销、全局访问、延迟加载。缺点：扩展困难、测试困难、可能导致状态污染。

在 AstroPaper 主题中添加新文章

更新于:2026年6月3日
|编辑此页

本指南介绍在 AstroPaper 中创建文章时需要遵循的规则和约定，包括文件位置、frontmatter 字段、图片和语法高亮。

目录

创建博客文章

要撰写新文章，请在 src/content/posts/ 目录中创建 Markdown（或 MDX）文件。

你可以使用子目录整理文章，子目录名会成为文章 URL 的一部分。例如，src/content/posts/2025/example-post.md 对应的页面地址是 /posts/2025/example-post。

如果只想通过子目录整理文件，而不让目录名影响 URL，请在目录名前加下划线（_）。

# 示例：文章文件路径及对应 URL
src/content/posts/very-first-post.md          -> mysite.com/posts/very-first-post
src/content/posts/2025/example-post.md        -> mysite.com/posts/2025/example-post
src/content/posts/_2026/another-post.md       -> mysite.com/posts/another-post
src/content/posts/docs/_legacy/how-to.md      -> mysite.com/posts/docs/how-to
src/content/posts/Example Dir/Dummy Post.md   -> mysite.com/posts/example-dir/dummy-post
Tip

以 _ 开头的文件和目录不会参与路由。你可以用它们存放草稿、共享资源或仅供内部使用的内容。

Frontmatter 元数据

Frontmatter 是存储文章元数据的主要位置，以 YAML 格式写在文件顶部。关于 frontmatter 的更多说明，请参阅 Astro 文档。

以下是文章 frontmatter 字段列表：

PropertyDescriptionRemark
title文章标题（h1）。必填*
description文章描述，用作文章摘要和该文章的站点描述。必填*
pubDatetimeISO 8601 格式的发布日期和时间。必填*
modDatetimeISO 8601 格式的修改日期和时间（仅在文章修改后添加此字段）。可选
author文章作者。默认值为 site.author
featured是否在首页的精选文章区域显示。默认值为 false
draft将文章标记为未发布状态。默认值为 false
tags文章相关关键词，使用 YAML 数组格式。默认值为 others
ogImage文章的 OG 图片，可用于社交分享和 SEO。可以是远程 URL，也可以是相对于当前目录的图片路径。默认使用 site.ogImage 或生成 OG 图片
canonicalURL规范 URL（绝对地址），用于标记已发布在其他来源的文章。默认使用 Astro.site + Astro.url.pathname
hideEditPost隐藏文章标题下方的编辑链接，仅对当前文章生效。默认值为 false
timezone使用 IANA 格式为当前文章指定时区；此设置仅覆盖当前文章的全局 site.timezone 配置。默认使用 site.timezone
Tip

在控制台运行 new Date().toISOString() 即可获取 ISO 8601 格式的日期时间。

Frontmatter 中必须提供的字段只有 title、description 和 pubDatetime。

标题和描述（摘要）对搜索引擎优化（SEO）很重要，因此 AstroPaper 建议每篇文章都填写这两个字段。

如果文章中没有填写 tags，系统会使用默认标签 others。你可以在 src/content.config.ts 中修改默认标签：

// ...
tags: z.array(z.string()).default(["others"]), // replace "others" with whatever you want
// ...src/content.config.ts

Frontmatter 示例

以下是文章 frontmatter 示例：

---
title: 文章标题
author: your name
pubDatetime: 2022-09-21T05:17:19Z
featured: true
draft: false
tags:
  - some
  - example
  - tags
ogImage: ../../assets/images/example.png # src/assets/images/example.png
# ogImage: "https://example.org/remote-image.png" # remote URL
description: 这是这篇示例文章的描述。
canonicalURL: https://example.org/my-article-was-already-posted-here
---src/content/posts/sample-post.md

VS Code 代码片段（可选）

AstroPaper 内置了工作区代码片段，可帮助你更快地创建文章：

  • frontmatter：插入推荐的 frontmatter 代码块
  • template：插入基础文章模板（包含 ## Table of contents）

这些代码片段位于 .vscode/astro-paper.code-snippets。如果你使用 VS Code（或 Cursor），打开工作区后即可使用。

提示框

AstroPaper 从 v6.1 开始支持提示框。它由 rehype-callouts（Obsidian 主题）提供支持，使用简单的引用块语法。

以下是最常用的类型：

Note

读者需要了解的补充信息。

Tip

有帮助的建议、快捷方式或最佳实践。

Warning

可能出错或造成意外后果的事项。

Danger

可能导致失败、数据丢失或行为异常的严重风险。

Info

中性的背景信息，紧急程度低于普通提示。

Success

确认某项操作成功或结果正确。

支持的类型包括：NOTE、ABSTRACT、INFO、TODO、TIP、SUCCESS、QUESTION、WARNING、FAILURE、DANGER、BUG、EXAMPLE、QUOTE，每种类型都有自己的图标和颜色。许多类型也支持别名（例如 TIP 可用 HINT 和 IMPORTANT，WARNING 可用 CAUTION）。完整说明请参阅 rehype-callouts 文档。

可折叠提示框

在类型后添加 -，可让提示框默认折叠；添加 +，则默认展开但仍可折叠：

Read before proceeding

读者展开提示框后才能看到这段内容。适合放置较长的注意事项，避免打断正文阅读。

Pro tip (expanded by default)

提示框默认展开，但可以折叠。适合放置希望首次阅读时可见的补充说明。

自定义标题

在类型后添加文字，即可用自定义标题替换默认的类型标签：

Did you know?

类型后面的文字会成为提示框标题。如果不填写文字，系统会自动使用类型名称。

语法汇总

> [!NOTE]
> Supplementary information.

> [!WARNING]- Collapsed by default
> Hidden until expanded.

> [!TIP]+ Expanded, but collapsible
> Starts open.

> [!DANGER] Custom title
> Replaces the default heading.

添加目录

默认情况下，文章不会显示目录（TOC）。如果需要添加目录，请使用二级标题 ## Table of contents，并将它放在希望目录出现的位置：

---
# frontmatter
---

这里可以放置在 AstroPaper 博客主题中创建文章的建议和技巧。

## Table of contents

<!-- 文章的其余内容 -->

标题层级

请注意：AstroPaper 使用 frontmatter 中的 title 作为文章的主标题。因此，正文中的标题应从 h2 到 h6 开始使用。

这不是强制规则，但出于视觉效果、易访问性和 SEO 的考虑，强烈建议遵守。

语法高亮

AstroPaper 默认使用 Shiki 作为语法高亮工具，并通过 @shikijs/transformers 增强围栏代码块。如果不需要这些 transformers，可以将其移除：

pnpm remove @shikijs/transformers
// ...
import {
  transformerNotationDiff,
  transformerNotationHighlight,
  transformerNotationWordHighlight,
} from "@shikijs/transformers";

export default defineConfig({
  // ...
  markdown: {
    remarkPlugins: [remarkToc, [remarkCollapse, { test: "Table of contents" }]],
    shikiConfig: {
      themes: { light: "min-light", dark: "night-owl" },
      defaultColor: false,
      wrap: false,
      transformers: [
        transformerFileName(),
        transformerNotationHighlight(),
        transformerNotationWordHighlight(),
        transformerNotationDiff({ matchAlgorithm: "v3" }),
      ],
    },
  },
  // ...
});astro.config.ts

存储文章图片

以下介绍两种存储图片并在 Markdown 文件中使用的方法。

Important

如果需要为 Markdown 中经过优化的图片设置样式，请使用 MDX。

存放在 src/assets/ 目录中（推荐）

你可以将图片放在 src/assets/ 目录中。Astro 会通过 Image Service API 自动优化这些图片。

引用图片时，可以使用相对路径或别名路径（@/assets/）。

例如，要显示路径为 src/assets/images/example.jpg 的 example.jpg：

![something](@/assets/images/example.jpg)

<!-- OR -->

![something](../../assets/images/example.jpg)

<!-- Using img tag or Image component won't work in markdown ❌ -->
<img src="@/assets/images/example.jpg" alt="something">
<!-- ^^ This is wrong -->
Tip

从技术上说，你可以把图片放在 src 下的任何目录中；这里只是推荐使用 src/assets。

存放在 public/ 目录中

你也可以将图片放在 public/ 目录中。请注意，Astro 不会处理或优化 public/ 中的图片，因此需要自行优化。

引用这些图片时请使用绝对路径。可以使用 Markdown 图片语法或 HTML img 标签显示图片。

例如，假设 example.jpg 位于 public/assets/images/example.jpg：

![something](/assets/images/example.jpg)

<!-- OR -->

<img src="/assets/images/example.jpg" alt="something">

其他建议

图片压缩

Warning

将图片添加到文章前（尤其是放在 public/ 目录中的图片），请先进行压缩。未经优化的图片会明显影响页面性能。

推荐的图片压缩网站：

  • TinyPng
  • TinyJPG

OG 图片

如果文章没有指定 OG 图片，就会使用默认图片。虽然并非必填，但建议在 frontmatter 中为文章指定相关图片。OG 图片的推荐尺寸为 1200 × 640 像素。

Tip

从 AstroPaper v1.4.0 开始，如果没有指定 OG 图片，系统会自动生成。详情请参阅功能介绍。
